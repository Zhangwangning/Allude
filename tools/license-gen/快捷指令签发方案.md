# 码夹 · 用快捷指令签发凭证（原理 + 搭建）

配套文件：`shortcut-shell.zsh`（快捷指令里粘贴的 Shell 片段）、`issue-openssl.py`（Python 版签发脚本）。

---

## 一、凭证的三段结构

一张凭证就是一条字符串，由 **两个句点**切成三段：

```
CLIP1 . eyJzIjoibW9udGhseSIsImQiOiJBQTExQkIyMkNDMzNERDQ0RUU1NUZGNjY3Nzg4OTkwMCIsImkiOiIyMDI2LTA5LTI0VDE0OjE2OjAyWiIsImUiOiIyMDI2LTEwLTI0VDE0OjE2OjAyWiJ9 . I-3jmk5yaqV2yI9YwBOk70RtWPiz9deWhj2Eemaisp99qwy10EY7xeRt9hwb6mk4PzbpR7cHuinZEFp58Sd-Ng
 ①                                ②                                                                                                        ③
```

| 段 | 名称 | 是什么 |
|---|---|---|
| ① | 版本前缀 | 固定字面量 `CLIP1`。参与签名，防止有人把前缀改掉后重放 |
| ② | 载荷 | 一段 JSON 的 **base64url** 编码 |
| ③ | 签名 | 对 `①.②` 整段的 **ECDSA P-256 + SHA-256** 签名，输出 P1363 格式后再 base64url |

把第 ② 段解出来看（真实的载荷长这样）：

```json
{"s":"monthly","d":"AA11BB22CC33DD44EE55FF6677889900","i":"2026-09-24T14:16:02Z","e":"2026-10-24T14:16:02Z"}
```

| 字段 | 含义 | 规则 |
|---|---|---|
| `s` | 档位 service | `monthly` / `yearly` / `lifetime` |
| `d` | 设备码 device | 买家 32 位大写十六进制码，**必填**；App 侧为空即拒 |
| `i` | 签发时间 issued | ISO8601，**不带毫秒** |
| `e` | 到期时间 expires | 同上；`lifetime` 档**不带这个字段** |
| `n` | 备注 note | 可选，只给卖家自己对账用 |

## 二、算法：四处细节，错一处就"签得出但验不过"

这四条是整件事的全部难度所在，也是 `issue.mjs` 文件头反复强调的四点：

### ① payload 的 JSON 文本本身就是签名对象
字段顺序固定 `s → d → i → e → n`，**中间不能有空格**。

```json
{"s":"monthly","d":"..."}     ✅ 签名对象
{"s": "monthly", "d": "..."}  ❌ 多了空格 = 完全不同的字节 = 验不过
```

顺序变了、空格变了，字节就变，签名对象跟着变。

### ② 载荷编码必须是 base64url，不是标准 base64

| | 标准 base64 | base64url（本方案） |
|---|---|---|
| 第 62 个字符 | `+` | `-` |
| 第 63 个字符 | `/` | `_` |
| 尾部填充 | 有 `=` | **全部去掉** |

所以标准 base64 编完后要再做三步：`+`→`-`、`/`→`_`、删掉所有 `=`。

### ③ 签名对象是 `CLIP1.<载荷>` 整段，不是只有载荷

App 侧验签时也是拿整段去验 —— 把版本前缀纳入签名范围，挡住"改改前缀"的玩法。

### ④ 签名必须是 P1363，不是 openssl 默认的 DER ← 最大的坑

ECDSA 的签名结果是一对整数 `(r, s)`，两种摆法：

```
DER（openssl 默认）  30 45 02 21 00 8d f7 … 02 20 3a c1 …    带 ASN.1 头、长度可变
P1363（App 要的）    <r 补足 32 字节> + <s 补足 32 字节>        固定 64 字节，无头
```

App 侧走 CryptoKit 的 `P256.Signing.ECDSASignature(rawRepresentation:)`，**只认 P1363**。
直接拿 openssl 的输出去拼凭证，结果是：**能签出来，App 一律判"校验未通过"**，且报错信息没有任何指向性。

转换规则（`shortcut-shell.zsh` 里那段 Python 就是干这个）：

```
DER:    30 <len>  02 <rLen> <r>  02 <sLen> <s>
P1363:  r 去掉前导 0x00 后左补到 32 字节  ‖  s 同样处理
```

## 三、结论先行：快捷指令能做什么、不能做什么

| 步骤 | 快捷指令原生动作 | 说明 |
|---|---|---|
| 文本拼接 payload | ✅ 有 | 「文本」动作 |
| base64 编码 | ✅ 有 | 「Base64 编码」动作，输出**标准** base64，需再替换 `-_` 并去 `=` |
| SHA-256 哈希 | ✅ 有 | 「生成哈希」动作（本项目用不上） |
| **ECDSA P-256 签名** | ❌ **没有** | 这是唯一的硬缺口 |
| DER → P1363 转换 | ❌ 没有（动作层面） | 需要按字节解析 |

**所以：iOS / iPadOS 上纯靠快捷指令动作，签不出凭证** —— 缺椭圆曲线签名这个原语，没有替代动作。

**可行路径是把"签名"这一步交给本机的 Shell**：

- **macOS 快捷指令**：「运行 Shell 脚本」动作 + 系统自带的 `openssl` / `python3` —— **推荐，已验证**；
- iOS 端想跑，得借 `a-Shell`、`iSH` 这类能在系统内提供 Unix 环境的 App（未验证，且私钥要上手机，**不推荐**，理由见第六节）。

## 四、方案 A（推荐）：macOS 快捷指令，四个动作

在 Mac 的「快捷指令」App 里新建，按顺序加：

### 动作 1 · 要求输入
- 问题：`粘贴买家设备码`
- 类型：**文本**（不要选数字 —— 十六进制含 A–F）

### 动作 2 · 从菜单中选取
- 提示：`选择档位`
- 选项与取值：

| 显示文本 | 传出的值 |
|---|---|
| 月付（30 天） | `monthly` |
| 年费（365 天） | `yearly` |
| 永久 | `lifetime` |

> 做法：每个选项点「编辑」把「值」填成上面的英文（显示文本保持中文）。
> 若嫌麻烦，也可以换成第二个「要求输入」，让卖家自己敲档位。

### 动作 3 · 文本
内容（用魔法变量插入前两步的结果，中间真正换行）：

```
[设备码]
[档位]
```

### 动作 4 · 运行 Shell 脚本
- Shell：**zsh**
- 输入：选「上一步的文本」（快捷指令会把它 pipe 到脚本的 stdin，脚本里用 `cat` 读）
- 脚本内容：**把 `shortcut-shell.zsh` 全文粘进去**

### 动作 5 · 拷贝至剪贴板
接动作 4 的「Shell 脚本结果」。

### 动作 6 · 显示结果
同样用「Shell 脚本结果」。

跑一次：输入设备码 → 选档位 → 剪贴板里就是那串 237 字符的凭证，直接粘给买家。

> **失败怎么读**：脚本失败时会输出 `ERR|…`（如 `ERR|设备码归一化后是 31 位…`）并返回退出码 1。建议在动作 4 后面加一个「如果」判断结果是否以 `ERR|` 开头，是就改用「显示提醒」弹出来。

## 五、方案 B：连 Shell 脚本都不写，一行调脚本

如果不想往快捷指令里粘几十行，只用**一个**「运行 Shell 脚本」动作：

```zsh
/usr/bin/python3 "/Volumes/ZWN/Downloads/Project/CodeClip/tools/license-gen/issue-openssl.py" \
  --service monthly --device "<粘贴设备码>"
```

档位用魔法变量替换 `monthly` 即可。这条更短，但依赖 `issue-openssl.py` 这个文件在位。

**两个方案的关系**：`shortcut-shell.zsh` 把全部逻辑写在动作里（自包含、与脚本文件解耦）；方案 B 把逻辑留在 Python 里（要点改算法时只改一处）。**日常签发建议用方案 A**，因为它不依赖仓库路径下的脚本文件，只依赖私钥。

## 六、本次实测证据

`shortcut-shell.zsh` 与 `issue-openssl.py` 的产出均交给**原有的 `issue.mjs --check`** 验签（两边算法独立实现，能互验即证明与 App 侧算法一致）：

| 验证项 | 结果 |
|---|---|
| Python 版签 → Node 版验 | `✓ 签名有效`，载荷字段齐全 |
| Node 版签 → Python 版验 | `✓ 签名有效` |
| 纯 Shell 管道签 → Node 版验 | `✓ 签名有效` |
| 篡改凭证任意一位 → 两边验签 | **均判无效** ✓（签名确实在起作用） |
| 档位 monthly / yearly / lifetime | 三种都对，lifetime 正确**不带 `e` 字段** |
| 设备码带连字符 / 小写 | 正确归一化为 32 位大写 HEX |
| 设备码 31 位 | 拒绝签发，输出 `ERR|…`，退出码 1 |
| 档位拼错（`quarterly`） | 拒绝签发，退出码 1 |

签发链路只用到 macOS 自带程序：`date` / `printf` / `base64` / `tr` / `sed` / `openssl` / `python3`。

## 七、红线与提醒

1. **私钥绝不进快捷指令文本、绝不进 iCloud Drive、绝不上手机。**
   快捷指令会把内容通过 iCloud 同步到其它 Apple 设备；一旦私钥文本进了动作，等于全设备可见。
   本方案的脚本里只写私钥的**文件路径**，私钥内容始终留在 Mac 本地磁盘 —— 这是刻意的设计。
2. **外置卷依赖**：脚本里的私钥路径在 `/Volumes/ZWN/…`。该卷未挂载时脚本会直接报 `ERR|找不到私钥…`。
   若嫌不稳，可把 `private-key.pem` 复制到一个本机固定目录（如 `~/.codeclip/private-key.pem`，权限 `chmod 600`），并同步改脚本里的 `KEY=`。
3. **档位与承诺必须一致**：淘宝写"一年"就发 365 天，别为留余量发 360 天 —— 到期日不对是最容易招差评的细节。
4. **凭证到期时间写死在签名里**，没有"续期叠加"。到期/换机一律按新到期日**签一张新的**让买家重新导入覆盖。
5. **发出前务必验一次**（`issue.mjs --check` 或 `issue-openssl.py --check`），确认绑的是对的那台设备 —— 这是售后最常出错的点。
