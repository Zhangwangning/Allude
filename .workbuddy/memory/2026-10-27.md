### 23:00 圆角与底部间距修正
🔴 **四角圆角的正确取法**：面板缩进 8pt 浮在遮罩上时，圆角必须按
**「屏幕圆角 − 缩进」** 取。
🔴 **iPhone 16 Pro / 18 Pro Max 的 `_displayCornerRadius` 实测都 = 72pt**（不是我一开始猜的 55！）。
所以面板 = 72 − 8 = **64pt**。先写 26、再写 46 都偏方，就是硬编码猜错的两连击。

**实现（逐机型自适应，覆盖 iPhone 11~18 Pro Max）**：
```swift
static var displayCornerRadius: CGFloat {
    let screen = (UIApplication.shared.connectedScenes.first as? UIWindowScene)?.screen
    if let r = screen?.value(forKey: "_displayCornerRadius") as? CGFloat, r > 0 { return r }
    guard let b = screen?.bounds else { return 55 }          // 拿不到屏幕
    return min(80, max(36, min(b.width, b.height) * 0.155))   // 比例兜底（系数由 402/72 反推）
}
```
- 私有键只读、全系直板机有效；各代圆角差异（X/XS≈39、12~14≈47、14Pro 起≈55、iOS26 这代 72）
  都由系统给出，代码里**没有任何固定数字**。
- 兜底按短边比例估算并夹在 [36,80]，最差差几 pt，不会像写死那样差 26pt。
- ⚠️ `UIScreen.main` 在 iOS 26 已废弃（会告警），必须用 `windowScene.screen`。

**双机型实测（AppKit 读像素，逐行量内缩轮廓）**：

| 机型 | 逻辑尺寸 | 面板距边 | 实测圆角 |
|---|---|---|---|
| iPhone 16 Pro | 402×874pt | L/R/T 均 8.0pt | 63.3pt |
| iPhone 18 Pro Max | 440×956pt | L/R/T 均 8.0pt | 63.3pt |

（这两代圆角规格相同，所以数值一致；换 12/13 会自动算出 39pt 左右。）
- 临时新建的 18 Pro Max 模拟器：`B26F46C7-D209-4D54-8A36-B511A185BED7`，留着以后验大屏。

## 00:10 为什么会「Xcode 账号自己没了」
时间线证据：Xcode 27.2 装于 **10-16**；`~/Library/Developer/Xcode/UserData` 最后变动 **10-22 13:35**；
唯一残留 profile 生成于 **10-22 19:13**（Widget 的）；主 App 的 profile **已不存在**。
⇒ 10-22 之后约 6 天没开过 Xcode **图形界面**（命令行 xcodebuild 不算登录会话）。
两层机制叠加：
1. **登录态**（Apple ID token）存在钥匙串（`Xcode-AlternateDSID` 等），有有效期，长期不启动不刷新就失效 →
   偏好里 `IDE.Identifiers.Prod` 变空，表现为"账号自己没了"。
2. **描述文件 7 天到期**（个人开发者计划），Xcode 会自动删过期 profile → 主 App 的那个先过期被清，
   只剩 Widget 那个还没到期的，于是看起来"profile 也凭空少了"。
🔴 **证书 ≠ 登录态**：`.p12` 私钥/证书能留一年（所以 `security find-identity` 一直有），
登录态几天就掉。两者分开过期，不是同一个东西。
**预防**：每 5–7 天打开一次 Xcode 界面（让它刷新 token）；
快速判断：`defaults read com.apple.dt.Xcode DVTDeveloperAccountManagerAppleIDLists`，`Prod = ()` 就是掉了。

## 00:15 手势两处修复：上滑误复制 / 长按要松手才弹
主人：「上滑屏幕的时候就很容易触发复制」「长按之后不动手要弹出菜单，不是等我松手后才弹出」。

**① 上滑误触发复制（`SwipeActionRow`）**
旧实现是**每一帧**各自比较 `|dx| > |dy|`：垂直滚动时手指稍斜，某一帧水平分量压过垂直，
offset 就开始动；而且 `onEnded` **完全不看方向**，`predictedEndTranslation.width` 在垂直滚动
结束时也常有几十 pt → 被判成「向右滑过六成」直接复制。
修复：新增 `lockedAxis`（首次判定 `|dx| > |dy|*1.5` 才锁 `.horizontal`，否则锁 `.vertical` 并整次不碰 offset）；
`onEnded` 先取 `wasHorizontal`、再校验一次 `|dx| > |dy|`，不满足就归零返回。
🔴 `minimumDistance` **保持 12pt**：误触不是它造成的（试过调到 20，只会让"轻扫 12pt 收起"变迟钝）。

**② 长按要松手才弹（`CardMenu`）**
根因是手势竞争：行内 `SwipeActionRow` 有 `DragGesture`，`.onLongPressGesture` 的识别器
要**等 Drag 失败**才能成立，而 Drag 的失败判定被推迟到手指抬起 → perform 实际在松手时跑。
修复：打开菜单改走 `.simultaneousGesture(LongPressGesture(minimumDuration: 0.34))`
（并行识别，满足时长立即 onEnded，手指可继续按着）；原来那个 `onLongPressGesture`
缩到 `minimumDuration: 0.05`、perform 留空，只用来上报 `pressing` 的按下回弹反馈。

⚠️ **真机构建必须带 `OTHER_SWIFT_FLAGS="-disable-sandbox"`**，否则宏失败报
`SwiftUIMacros.StateMacro could not be found`。⚠️ 而且不能把 build 和 install 用 `&&` 串在一起 ——
`grep` 命中 error 行也返回 0，会继续执行 install，把**上一版的旧包**装进手机。

## 00:18 长按时长 0.34 → 0.45，改 highPriorityGesture
