## 码夹 iOS · 锁屏实时活动「重复两张卡」根治

- **现象（主人截图）**：锁屏上并列两张实时活动卡，**取件码不同** —— `118-5-6178`（上）/ `110-5-6178`（下），平台与地址相同（菜鸟驿站 · 临沂大学菜鸟驿站）。
- **取证脚手架**：`CodeClipApp.swift` 新增 `SCREEN=activityRace`（分 A~E 五阶段）+ `raceLog` 落盘（`simctl launch --console` 在非交互 shell 里拿不到 stdout，只能写 Documents 再拷出）。
  - ⚠️ 必须同时注入 `PLAN=yearly`：实时活动是 VIP 权益，全新安装的模拟器没有凭证 → `isPro=false` → 第 1 道门直接 `endAll()` → 读到 `running=0`，极易误判成「模拟器不支持活动」。脚手架里另加一条独立 `probe`，把 request 的**错误原文**打出来。
- **两条根因（都实测复现）**：
  1. **读-判-写竞态**：`Activity.activities` 读 + `Activity.request` 非原子。账本清空后 24 个并发 sync → **稳定产生 3 张**（两次 sync 重叠的真实形态：`records` 的 `didSet` 与 App 被静默拉起后 `scenePhase=.active` 的 `reloadFromStorage` 挤在同一秒）。
  2. **账本同步延迟**（解释「两张卡取件码不同」）：新拉起的进程读到空列表 → 又 request 一张，旧的冻结在旧内容上成了幽灵卡。
  - 放大器：`converge` 只 `update(activities.first)`，**多余活动永不消失**（实测：人为造 5 张后「再 sync 一次」完全收敛不了 —— 收敛前 5、收敛后 5）。
- **修法**（`CodeClipShared/PickupActivityController.swift` 重写）：
  - `sync` 改**单飞 + 合并**：`@MainActor` 的 `latest` / `converging` + `while let next = latest` 消费最新值 —— 任一时刻只有一条收敛链，`converge` 不可能与另一个自己重叠。
  - 新增 `enforceSingle(preferring:)`：**每次收敛出口**清掉保留者之外的活动；保留策略**优先内容匹配者**（否则会留一张过期卡）。
  - 新增 `settle()`：`enforceSingle` → 睡 1.2s → **再 enforceSingle**（收「迟到的旧活动」；刚 request 完立刻查往往只看到自己那张）。
  - 拆出 `apply(state)`（只负责把内容对齐），`converge` = 四道门 + `apply` + `settle`。
- **自愈入口**（`CodeClipApp.swift`）：回前台**无条件** `sync` 一次（原本只在 `reloadFromStorage` 内容签名变化时才同步 ⇒ 重复卡不改变数据 ⇒ 永远等不到收敛）；冷启动补一次对齐（`SCREEN` 注入时跳过）—— `Activity.request` 要求前台，须延后到 UIScene 连上（实测 init 期间发起的会被拒，同刻探针却成功）。
- **量化验收**（`CodeClip/tools/activity-race/run.sh` 可复跑，报告归档 `report-*.txt`）：

  | 阶段 | 修复前 | 修复后 |
  |---|---|---|
  | 账本清空 + 24 并发 sync | **3 FAIL** | 1 PASS |
  | 顺序连发 24 次 | 3 FAIL | 1 PASS |
  | 人为造重复卡（复现截图画面）→ 一次 sync | **5 FAIL（收敛不了）** | 1 PASS |
  | 同步后注入「迟到的旧活动」 | — | 1 PASS（延迟复查收掉） |

- **取证工具链的坑**：
  - `simctl terminate` 有时不生效 —— `launch` 返回的 PID 与上轮相同就说明 App 从未重启、脚手架没跑；对比两次 `probe` 的 UUID 可判定报告是否本轮生成。
  - 报告是 append 写；多轮跑完要辨认段落（脚本里先 `uninstall`）。
  - **ActivityKit 对 request 有频率节流**：连续压测后被拒 ⇒ `duplicated running=1` 是「没造出来」而非「修复生效」、`running=0` 是「没起来」。对策：每处 request 都打错误原文；怀疑节流就**重启模拟器**复位。
  - 判定脚本不能用裸 `grep FAIL`（脚手架说明文字含 "PASS/FAIL" 会误伤），改 `grep -qE "running=[0-9]+ FAIL"`。
- **沉淀**：新建技能 `~/.workbuddy/skills/ios-live-activity`（单一性不变式、竞态、账本延迟、触发点清单、取证脚手架设计、节流坑、暗色锁屏/灵动岛取色与尺寸）。项目内 `CodeClip/tools/activity-race/`（脚本 + 前后对照证据）。

## 发码.app 主菜单与本地化（同日深夜，用户反馈「⌘V 粘不进来 / 拷贝是英文的」）

- **根因（两个独立问题，均经实测钉死）**：
  1. **纯代码（无 nib）App 不设 `NSApp.mainMenu` ⇒ 系统只给一个「应用名」顶级菜单，没有「编辑」菜单**
     ⇒ ⌘C/⌘V/⌘X/⌘A/⌘Z **全部无人响应**（AppKit 快捷键由主菜单 keyEquivalent 分发，`NSTextView` 自己不管）。
     对照实验：不装菜单 `performKeyEquivalent=false`，装了就 true 且真能粘贴；同时 `firstResponder == NSTextView`、
     直连 `paste(nil)` 可用 —— 一次性排除了「焦点 / 可编辑性 / 剪贴板」三个错误方向。
  2. **`Bundle.main.localizations == []`**（Info.plist 无 `CFBundleDevelopmentRegion`、bundle 内无任何 `.lproj`）
     ⇒ 系统提供的那部分 UI 全是英文：NSTextView 右键 `Cut/Copy/Paste`、编辑菜单自动追加的
     `AutoFill / Start Dictation… / Emoji & Symbols`、窗口菜单 `Close All`。
- **改动**：
  - 新增 `macapp/Src/MainMenu.swift`（应用 / 编辑 / 窗口三菜单，全中文；编辑项 target 一律 nil 走响应链）。
    `main.swift` 在 `app.run()` 前调 `MainMenu.install()`，并把菜单结构写进 ccLog 便于真机诊断。
  - `build.sh`：Info.plist 补 `CFBundleDevelopmentRegion=zh-Hans` + `CFBundleLocalizations` +
    `NSHumanReadableCopyright`；生成 `Contents/Resources/zh-Hans.lproj/InfoPlist.strings`
    —— **该目录存在本身就是触发系统 UI 中文化的条件**。
- **验证（两套，职责别混）**：
  - `verify/run.sh` ⑥ 段 = **结构审计**（顶级菜单 `["发码","编辑","窗口"]`、8 个快捷键项齐全、无一钉死 target）。
  - 新增 `verify/menu/run.sh` = **行为验证**（真实 .app：复制 `build/发码.app` 的 Info.plist+Resources，只换可执行文件，
    避免维护两份 plist）。实测：对照组（无菜单时 ⌘V 无效）✓、⌘V/⌘A/⌘C/⌘X/⌘Z/⇧⌘Z 全 ✓、右键菜单已中文化 ✓，连跑 2 次稳定 PASS。
- **本轮踩到四个新坑（已沉淀 `macos-app-dev-pitfalls`）**：
  1. `NSMenuItem()` 无参构造出的项 `title` 是字符串 **"NSMenuItem"**（类名），不是空串 —— 菜单栏会字面显示类名。
  2. 「粘贴并匹配样式」的 action 是 **`pasteAsPlainText:`**；`pasteAndMatchStyle:` NSTextView **不响应**（挂了会永远变灰）。
  3. ⇧⌘Z 的 `charactersIgnoringModifiers` 是**大写 "Z"**（该属性忽略的是「除 Shift 外」的修饰键），
     故「重做」的 keyEquivalent 必须写 **"Z"**，否则按下毫无反应。
  4. `NSUndoManager` 的 undo 分组边界**时好时坏**（嵌套 `RunLoop.run` 与 `asyncAfter` 间隔都不保证 run loop 进 waiting）
     ⇒ 断言改用 `undoManager.removeAllActions()` 清栈，让结果与分组无关。
- **经验：命令行 harness 测不了快捷键** —— 无 bundle 进程 `isKeyWindow` 恒 false，`target(forAction:)` 必然落空（假警报）。
  行为验证已整体搬到真实 .app（`verify/menu/`）。
- **现状**：release 已装到 `/Applications/发码.app` 并正常运行；调试开关、探针缓存均已清除。
