# 2026-10-15 工作日志

## 详情页「快递驿站 / 取件地址」字段拆分（主人 13:21 指正）

**问题**：主人发现详情编辑页「快递驿站」行显示的是「即墨区闫家岭小区西区林成驾校店」——这是取件地址，不是驿站。

**根因**：`RecordDetailView.swift` 原第 366 行 `editableBlock(label: "快递驿站", value: record.address, keyPath: \.address, ...)`——标签叫驿站，绑的却是 address 字段。PickupRecord 模型里**没有独立 station 字段**，驿站名一向是列表卡片显示时 `StationDirectory.matchedName(in: [address, rawMessage])` 实时匹配算的，不落库。

**修复**（主人定案：改标签 + 新增驿站行，匹配到才显；匹配范围维持短信+地址）：
- 「取件地址」= record.address（原行改标签，可编辑补填）
- 「快递驿站」= matchedName 实时值，只读不可手改；只读态匹配不到整行隐藏，编辑态显「未识别」弱化占位
- 字段顺序：取件码 → 取件平台 → 快递公司 → 快递驿站 → 取件地址 → 货架号 → 运单号 → 尾号 → 添加时间
- RecordDetailView 加 `@ObservedObject stationDirectory`，自定义驿站改名/删图后详情行同帧刷新

**概念口径（主人原话）**：「取件地址是取件地址，快递驿站是固定的驿站或者商铺」。门店名（如韵达加盟店「林成驾校店」）千变万化不进固定词表，匹配不到即无驿站，卡片走 courier 兜底——属规则行为。

## 工程踩坑

- **iOS 27 SDK**：`UIColor.tertiaryLabelColor` 已更名 `tertiaryLabel`（编译报错 renamed to）。
- **simctl launch 环境变量必须带 `SIMCTL_CHILD_` 前缀**：直接 `GALLERY_ANCHOR=x` 前缀不透传给 app 进程（App 侧读的是剥前缀后的名字）；曾因漏前缀白跑一轮截图。
- `simctl launch --console` 会持续跟随 stdout 不退出，管道 grep 会被 SIGTERM（exit 137）；验证 print 输出别用 --console。
- CourierGalleryView 已有 `anchor` 参数（ScrollViewReader 滚到分类 section），App 入口现接 `SIMCTL_CHILD_GALLERY_ANCHOR`（值 = 分类 rawValue，如「驿站 / 代收平台」「智能快递柜」）——一屏放不下所有分类，以后验收任何分类走这个。
- 冷启动 RootView（DETAIL_MATCH 找不到记录时的回落）首帧渲染慢，截图需 sleep ≥4s，否则白屏误判。
