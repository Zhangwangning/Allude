# 2026-11-17

## 驿站组 / 驿站 ID 化 / 驿站内排序（构建 320）

老大的设计，前几轮只讨论，这一轮落地并打进 320（319 已在 TestFlight，只能升号）。

### 数据模型
- 新增 `AlludeShared/StationGroups.swift`（App + Widget 两个 target，需手动进 pbxproj 三处）。
- `StationIdentity`：全驿站 ID 化，`NZYZ00001…` / `DZYYZ00001…` / `FZYD00001…`，
  **首次发号落盘固化**（App Group `station-identity.json`），之后只追加末尾 ——
  不能按 `CourierBrand.table` 下标实时算，中间插品牌会让老 ID 整体后移、组关系错位。
- `StationGroup`：`id/name/memberIDs/createdAt/iconInheritMemberID/locationInheritMemberID`，
  存 `station-groups.json`。
- 关系挂**成员 ID**，成员改名走 `StationIdentity.rename`，组里不会出现幽灵成员。
- 三段优先级：组驿站 > 未归组驿站 > 组内成员。⚠️ ID 前缀是「来源三类」，
  三段是「是否被归组」算出来的，两者不是一回事 —— 只有 `FZYD` 能靠前缀认出来。

### 渲染同源
- `PickupSortLogic.stationName` → `StationGroupStore.displayName`（组名）。
- `PickupNaming` 新增 `stationGroup` + `secondaryLabel`，卡面副名 = 「组名/成员原名」。
  四个视图（待取卡 / 已取卡 / 详情 / 分享卡）的 `titleSecondary` 全部改成 `secondaryLabel`。
- 小组件 / 灵动岛走同一条 `PickupStorage.load()`，读盘时清 `StationGroupStore` /
  `StationIdentity` 缓存，避免「App 里归了组、桌面还分两坨」。
- `StationLogo` 支持组：继承成员（内置品牌走 `CourierLogo`、自定义走 `iconFiles`）
  → 组自己的图（key = 组 ID）→ 组名首字。**第一次截图踩到只查 iconFiles 的坑**，
  「恒大御府驿站」画成了「恒」。

### 驿站内排序
- `StationInnerOrder` 四档：时间新→旧 / 旧→新、取件码 0→9 A→Z / 9→0 Z→A。
- 逐字符字典序（`-` < `0` < `A`），`8-4-1005` < `8-4-3019` < `8-4-999`。
- 🔴 修掉一处老逻辑：`stationGroups` 建桶后又按时间重排一次，会把用户选的排序整个覆盖。
- `isOrderedBefore(_:_:moment:)` 允许调用方传时间口径（待取页 `lastNotifiedAt`，
  已取页 / 小组件 `receivedAt`），不强行统一。
