# 2026-11-16

## Duo 内屏竖屏丢大标题（根因）+ 竖屏单列 + 订阅页收窄 → 发版 316（主人验收通过）

### 🔴 根因：全局 `UINavigationBarAppearance` 清空了大标题文字属性
主人报「Duo 内屏竖屏时统计和设置页标题不见了」。现象是**大标题占位还在（顶部一大片留白）、
文字一个都不画**，并且只有 regular 宽度（内屏竖屏 762pt）复现，外屏 compact 正常。

真凶是 `AlludeApp.init()` 里 2026-11-15 加的那套：
```swift
let navAppearance = UINavigationBarAppearance()
navAppearance.configureWithOpaqueBackground()
navAppearance.backgroundColor = .systemGroupedBackground
UINavigationBar.appearance().standardAppearance = navAppearance
// …compact / scrollEdge / compactScrollEdge
```
用 `PLAIN_NAVBAR=1` 跳过它做对照 → 标题立刻回来。**`UINavigationBarAppearance` 整体替换后
`largeTitleTextAttributes` 变成空值**，系统不补默认值，于是不画字。

**这套本来就该删**：它当时是为「待取左上角白块」加的，但那次真正的修复是
`RootView` 给 TabView 铺 `systemGroupedBackground` 窗口底色（iOS 26 玻璃导航栏取样窗口背景）。
删掉后**待取/已取/统计/设置四页标题全正常，白块也没回来**（已截图验证）。

教训：自定义 `UINavigationBarAppearance` 必须显式补
`largeTitleTextAttributes` / `titleTextAttributes`，或者干脆别碰 appearance proxy。

### Duo 三个状态要分别验（主人强调）
外屏 / 内屏横屏 / 内屏竖屏。本轮结论：
- 内屏竖屏 = 单列（`isExpandedFoldable` 加 `width > height`），762×1080
- 内屏横屏 = 分栏，951×669，左列 466pt，自绘 34pt 大标题，无白块 ✓
- 外屏 = compact，等价普通 iPhone（466pt 高，订阅页需滚动属正常）

⚠️ 模拟器 `--display=3` 内屏、`--display=1` 外屏；**姿态会自己变**（同一 UDID
一会儿 762×1080、一会儿 1080×762）。截图先 `sips -g pixelWidth` 确认朝向再解读。
⚠️ **shutdown/boot 之后设备回到折叠态**：内屏黑屏，只会显示外屏；而且内屏启动慢，
实测要等 20–40 秒且 App 未必能起来。**别靠重启模拟器来「复位」**，代价是丢掉内屏。

### 无 GUI 环境转不了屏 → 加 `FORCE_SPLIT` 脚手架
`open -a Simulator` 找不到应用（Xcode 在 `/Volumes/ZWN/Applications/Xcode.app`，
其下没有 `Developer/Applications/Simulator.app`），System Events 仍 -10004。
`PadLayout.isExpandedFoldable` 里加 `#if DEBUG` 的 `FORCE_SPLIT=1` 强制分栏。
⚠️ **竖屏下强制分栏 ≠ 横屏分栏**：762×1080 时 `NavigationSplitView` 会自己把左列折叠成
detailOnly，只能用来验「左列 UI 组件颜色/字色」，不能验布局。

### 订阅页（PaywallSheetSizing）实测矩阵
| sizing | 宽度 | 高度 | 结论 |
|---|---|---|---|
| `.form` | 铺满整屏 | 满 | Duo 上完全无效 |
| `.page` | 几乎铺满 | 满 | 内容全显示但太宽 |
| `.fitted` 只给 `minHeight` | 居中窄卡片 | 被 clamp 到 ~890 | 底部差一条 |
| `.fitted` 只给 `width` | — | **塌成一条横条** | 不能只给宽度 |
| `fitted(horizontal:vertical:)` | — | **算出 0，弹层不可见** | 实例方法，链式能编译但是坑 |
| `.fitted` + `minWidth/idealWidth/maxWidth + minHeight` | 见下 | ~895 | ✅ 采用 |

**316 采用 `420 / 450 / 470 + minHeight 1000`**（横屏实测渲染 515pt、弹层吃满高度；
主人验收「合适」）。同一套参数在 460/500/520 时渲染约 570pt，也验过一屏装得下。
⚠️ 别只凭横屏结果推竖屏：横屏可用高 762、竖屏 1080，弹层上限 895。
内容自然高度在窄档约 950 → 竖屏会超，宽档约 890 → 刚好。

配合的内容收紧（`FullVersionView`）：外层 spacing 18→10、planCard vertical 16→12、
说明行 34→30、标题 26→24pt、bottom padding 20→8。直板机回归截图确认仍一屏显示完、
底部「隐私政策 · 使用条款」完整可见。
