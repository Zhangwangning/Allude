## Duo 内屏竖屏丢大标题（根因）+ 竖屏单列 + 订阅页收窄 → 发版 316（主人验收通过）

### 🔴 根因：全局 `UINavigationBarAppearance` 清空了大标题文字属性
主人报「Duo 内屏竖屏时统计和设置页标题不见了」。现象是**大标题占位还在（顶部一大片留白）、
文字一个都不画**，并且只有 regular 宽度（内屏竖屏 762pt）复现，外屏 compact 正常。

真凶是 `AlludeApp.init()` 里 2026-11-15 加的那套：
```swift
let navAppearance = UINavigationBarAppearance()
navAppearance.configureWithOpaqueBackground()
navAppearance.backgroundColor = .systemGroupedBackground
UINavigationBar.appearance().standardAppearance = navAppearance
// …compact / scrollEdge / compactScrollEdge
```
用 `PLAIN_NAVBAR=1` 跳过它做对照 → 标题立刻回来。**`UINavigationBarAppearance` 整体替换后
`largeTitleTextAttributes` 变成空值**，系统不补默认值，于是不画字。

**这套本来就该删**：它当时是为「待取左上角白块」加的，但那次真正的修复是
`RootView` 给 TabView 铺 `systemGroupedBackground` 窗口底色（iOS 26 玻璃导航栏取样窗口背景）。
删掉后**待取/已取/统计/设置四页标题全正常，白块也没回来**（已截图验证）。

教训：自定义 `UINavigationBarAppearance` 必须显式补
`largeTitleTextAttributes` / `titleTextAttributes`，或者干脆别碰 appearance proxy。

### Duo 三个状态要分别验（主人强调）
外屏 / 内屏横屏 / 内屏竖屏。本轮结论：
- 内屏竖屏 = 单列（`isExpandedFoldable` 加 `width > height`），762×1080
- 内屏横屏 = 分栏，951×669，左列 466pt，自绘 34pt 大标题，无白块 ✓
- 外屏 = compact，等价普通 iPhone（466pt 高，订阅页需滚动属正常）

⚠️ 模拟器 `--display=3` 内屏、`--display=1` 外屏；**姿态会自己变**（同一 UDID
一会儿 762×1080、一会儿 1080×762）。截图先 `sips -g pixelWidth` 确认朝向再解读。
⚠️ **shutdown/boot 之后设备回到折叠态**：内屏黑屏，只会显示外屏；而且内屏启动慢，
实测要等 20–40 秒且 App 未必能起来。**别靠重启模拟器来「复位」**，代价是丢掉内屏。

其下没有 `Developer/Applications/Simulator.app`），System Events 仍 -10004。

### 订阅页（PaywallSheetSizing）实测矩阵
| sizing | 宽度 | 高度 | 结论 |
|---|---|---|---|
| `.form` | 铺满整屏 | 满 | Duo 上完全无效 |
| `.page` | 几乎铺满 | 满 | 内容全显示但太宽 |
| `.fitted` 只给 `minHeight` | 居中窄卡片 | 被 clamp 到 ~890 | 底部差一条 |
| `.fitted` 只给 `width` | — | **塌成一条横条** | 不能只给宽度 |
| `fitted(horizontal:vertical:)` | — | **算出 0，弹层不可见** | 实例方法，链式能编译但是坑 |
| `.fitted` + `minWidth/idealWidth/maxWidth + minHeight` | 见下 | ~895 | ✅ 采用 |

**316 采用 `420 / 450 / 470 + minHeight 1000`**（横屏实测渲染 515pt、弹层吃满高度；
主人验收「合适」）。同一套参数在 460/500/520 时渲染约 570pt，也验过一屏装得下。
⚠️ 别只凭横屏结果推竖屏：横屏可用高 762、竖屏 1080，弹层上限 895。
内容自然高度在窄档约 950 → 竖屏会超，宽档约 890 → 刚好。

配合的内容收紧（`FullVersionView`）：外层 spacing 18→10、planCard vertical 16→12、
说明行 34→30、标题 26→24pt、bottom padding 20→8。直板机回归截图确认仍一屏显示完、

## 318：Duo 内屏竖屏「外观与个性化 / 关于 Allude」子项全部点不动

### 🔴 根因：分栏判定只看了屏幕宽度
主人报：Duo 内屏竖屏下，外观与个性化里的四项、关于 Allude 里的五项全部点不进去，
其他功能正常。

`ProfileView.destination(_:)` 里给 `AppearancePersonalizationView` / `AboutAlludeView`
传 `openPane` 的条件是 `horizontalSizeClass == .regular`。而 **Duo 内屏竖屏宽 762pt，
同样是 regular** —— 于是子行被渲染成 `Button { openPane(item) }`，点下去只改了
`pane = item`；可竖屏走的是 `stackedSettings` 单列分支，`pane` 没有绑定任何导航，
**一点反应都没有**。

### 修法：抽出 `isSplitLayout`，与选布局的条件共用
```swift
private var isSplitLayout: Bool {
    PadLayout.usesSplit
        && horizontalSizeClass == .regular
        && ProcessInfo.processInfo.environment["SETTINGS_COMPACT"] != "1"
}
```
替换四处（都是同一个根因的不同表现）：
1. `body` 里选 `splitSettings` / `stackedSettings`
2. `AppearancePersonalizationView(openPane:)`
3. `AboutAlludeView(openPane:)`
4. `HelpCenterView { pane = $0 }` 与 Pro 横幅的 `Button { pane = .license }`

分栏态条件原样搬进去，**行为零变化**；单列态现在拿到 nil，走 `NavigationLink`。

### 验证
加了一条 `#if DEBUG` 探针（`SettingsView.onAppear`）：
`[allude-layout] isSplit=false sizeClass=regular` —— Duo 内屏竖屏实测拿到这行，
证明判定与渲染已经一致。分栏态没条件实测（转不了屏），但条件是原样搬运。

### 发版
318（`7048ea25`）挂「Allude公测」，Beta 审核 submitted，测试内容 473 字。
同时 `PATCH /v1/builds/{id} {expired:true}` 把 **317**（上传过但一直没挂群组）和

### 教训
「宽屏」不等于「分栏」。任何 `horizontalSizeClass == .regular` 的判断都要问一句
「是不是真的在分栏」；两者在 Duo 内屏竖屏下会分叉。以后统一走 `isSplitLayout`。


## Duo 内屏横屏 AI 子树点不进去 → 改走「切右栏」（提交 0541df0）

### 症状
外屏 / 内屏竖屏 / 直板机都正常，**只有 Duo 内屏横屏（分栏）**下
「Apple 智能与扩展」里的 Apple 智能、扩展两个入口点不动。

### 根因（与本 bug 同一类，但机理不同）
分栏右栏的根内容是 `paneContent(pane)`：左列一换选中项，这棵树就被整棵替换。
往这种「随时会被换掉」的容器里再 push 一层，系统把推入当**无效操作丢掉** ——
日志能证明 push 被调用、界面纹丝不动。

试过全部失败：去 `NavigationStack(path:)`、去 `.id(pane)`、
在 `AIExtensionsHomeView` 内部注册 `navigationDestination(isPresented:/item:)`、
在栈根注册 value-based。**分栏下 `NavigationLink` 整体不可用**。

### 最终修法
分栏下唯一可靠导航 = **切 `pane`**（外观与个性化 / 关于 Allude / 帮助页一直是这套）。
- `SettingsPane` 加三个**内部面板** `aiAppleIntelligence` / `aiExtensions` / `aiUsage`，
  不进任何目录数组，只为右栏当内容用；`title`/`symbol`/`tint` 三处 switch 要补分支
- `AIExtensionsHomeView` / `AIExtensionsListView` 加 `openPane: ((SettingsPane) -> Void)?`
  - 非 nil（分栏）→ `Button { openPane(...) }` + `.buttonStyle(.plain)`
  - nil（单列）→ **destination 型** `NavigationLink {}`，绝不能改 value-based
    （外层 destination push 的栈里 value push 不落地）
- 扩展列表里点服务商：分栏改用页内 `@State inlineProvider` 换详情 + 自绘返回按钮
- 删掉 `AIProviderRoute` / `AIProviderDestination` 与两处 `navigationDestination` 注册
- 返回按钮条件扩到两个 AI 子面板，回到 `.aiCapability` 而不是 `.help`

### 验证
构建 0 error 0 warning；三张面板截图（aiAppleIntelligence / aiExtensions / aiUsage）渲染正常。
⚠️ 本机没有 Simulator GUI，转不了屏，分栏态靠 FORCE_SPLIT=1 脚手架渲染（`PadLayout.isExpandedFoldable`），
真实横屏仍需真机确认。

### 状态
改动已提交（0541df0），**主人叫停打包，319 未归档未上传**。
版本号已改 319，`BetaBuildLog` 与 `tools/testflight-notes/1.0.0-319.md` 已写好，等许可即可走发版流程。
