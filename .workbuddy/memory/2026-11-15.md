## 二、🔴 本机无法完整构建（环境限制，非代码问题）

`xcodebuild` 必然失败于 `CoreMLModelCompile` / `CoreMLModelCodegen`：

```
sandbox-exec: sandbox_apply: Operation not permitted
```

- 根因：Xcode 的 CoreML build rule **硬编码**用 `/usr/bin/sandbox-exec -f <profile>` 包住编译器；
  当前 agent 运行环境（seatbelt）不允许 apply 任何**非最简**策略。
- 实测边界：`sandbox-exec -p '(version 1)(allow default)'` 可以；
  加 `(import bsd.sb)`、`(disable-callouts)`、`(deny file-write* (subpath …))` 任一条即 71 失败。
- 试过且无效：`ENABLE_USER_SCRIPT_SANDBOXING=NO`、`dangerouslyDisableSandbox`。
- 手工 `coremlc generate` + `coremlc compile` 产出到 DerivedData 后重跑，仍会重建该任务 —— 绕不过。
- 结论：**构建验证必须在宿主终端（普通 shell）里跑**，或让主人跑一次；本会话内无法自证 0 warning。
  其余工程纪律（`-disable-sandbox`）不变。

## 六、🔴 绕过「agent 内不能构建」的可行办法（实测通过）

临时把 CoreML 模型移出编译，改用 `coremlc` 预生成的 Swift，构建完立刻还原：

```bash
# 1) 生成类型定义
xcrun --sdk iphonesimulator --show-sdk-path                     # 备用
coremlc generate <repo>/Allude/Allude/Resources/AlludePickup.mlmodel /tmp/coreml-gen \
  --language Swift --swift-version 5.0 --platform ios --deployment-target 17.0 --sdkroot <SDK>
# 2) 摘掉模型、顶入生成代码（同步组会自动编入 Models/ 下新文件）
mv Allude/Allude/Resources/AlludePickup.mlmodel{,.bak}
cp /tmp/coreml-gen/AlludePickup.swift Allude/Allude/Models/
# 3) 正常构建（此时无 CoreML build rule，不再有 sandbox_apply 失败）
xcodebuild ... build CODE_SIGNING_ALLOWED=NO OTHER_SWIFT_FLAGS="-disable-sandbox"
# 4) 还原
mv Allude/Allude/Resources/AlludePickup.mlmodel{.bak,}; rm Allude/Allude/Models/AlludePickup.swift
```
- 产物里没有 `.mlmodelc`，CoreML 相关功能不可用 —— **只用于 UI/布局验证**，不能发版。
- `swiftc -typecheck -disable-sandbox -sdk <iphonesim SDK> -target arm64-apple-ios17.0-simulator`
  + 全量 swift + 生成的 `AlludePickup.swift`，可在不构建的情况下做完整类型检查。
