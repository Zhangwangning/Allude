## 🔴 重复短信改为「更新时间 + 记历史」（00:30 主人定稿）

### 旧口径错在哪
`PickupMerge` 原逻辑：同指纹命中待取旧条 → **旧条标已取 + 新条入列**。
后果：替用户宣布"这件取了"（他根本没取）、统计平白多一次已取、停留时长被算成 0；
一旦 merge 没拦住（并发/历史数据）还会留下两条一模一样的待取。

### 新口径
命中同指纹的待取条 → **不新建、不改已取**，只做两件事：
```swift
working[index].history = (history ?? [receivedAt]) + [candidate.receivedAt]
```
- `PickupRecord.history: [Date]?`（新字段，Optional 兼容旧数据）
- `lastNotifiedAt { history?.last ?? receivedAt }` → 卡片右上角时间用它
- `receivedAt` **保持首次**不动 → 统计页停留时长不受重复通知干扰
- `Result.completed` 恒空（旧口径产物，保留兼容）

### 存量清洗
`PickupStore.dedupeIdenticalRecords()`（init 里在 sanitize 之后跑）：
按指纹合并重复的**待取**记录，留 receivedAt 最早那条，history 合并去重排序，其余删除。
已取记录一律不碰。

### 实测（真机 group.json）
- 待取重复码：**0**
- `7-4-2011` 从 2 条 → 1 条，`history = [21:51:20, 21:51:35]`，receivedAt 仍是 21:51:20
### UI
详情页新增「通知历史（N 次）」，每行 `M月d日 HH:mm:ss`（到秒，否则十几秒之差会显示成两行一样的时间）。

## 🔴 回归事故：粘贴已存在的短信 → 生成「手动添加」垃圾记录（00:40）

### 因果链（我改 merge 语义的连带破坏）
1. merge 从「旧条已取 + 新条入列」改成「只更新时间」→ `added` 变空；
2. 添加页 `submit()` 的兜底条件是 `if outcome.added.isEmpty { addManual(整段文本) }`；
3. 于是粘一条**已存在**的短信 → 被当成裸码 → `code = 整段原文`，
   列表出现「手动添加 / 快递超市 / 您的圆通快递包裹已…」的垃圾卡。

### 修法
```swift
let recognized = !PickupParser.parseAll(model.trimmed, ocrSource: true).isEmpty
if !recognized, model.looksLikeBareCode { outcome = store.addManual(...) }
```
两个条件都要满足才兜底：**解析器一条没认出来** + **输入确实像裸码**（无空格/标点/换行、≤48 字）。

### 脏数据清理
`PickupStore.purgeInvalidCodes()`（init 末尾）：
取件码含空白、含 CJK（≥0x2E80）、超过 24 字 → 判为脏数据删除。
真机实测：脏码记录 **0**，「手动添加」记录 **0**，待取 6 条正常。

⚠️ 教训：改「写入语义」（added/completed 的含义）时，必须排查所有拿它做分支判断的地方。
