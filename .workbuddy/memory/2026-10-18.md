# 2026-10-18

## 码夹短信解析三字段口径改造（主人定稿）
- 主人明确口径：短信平台 = `【】` 内内容；快递公司 = 正文（`【】` 外）优先匹配 → `【】` 内兜底（须是真快递公司）→ 无则空；快递驿站 = **仅从短信原文**匹配的实在品牌名（菜鸟裹裹 / 兔喜生活等），与取件地址解耦，无则空。
- 落地改动：
  - `PickupParser.company(from:)`：去掉正文回落与「未知快递」哨兵，严格返回 `【】` 内（无则空）。
  - `PickupParser.courierCompany`：顺序反转——先 `stripBracket` 后在正文找词根，正文无再看 `【】` 内白名单；去掉末尾 company/courier 互为回填。
  - `CourierBrand`：新增主流驿站 / 柜品牌（极兔邻里、百世邻里、中通 / 申通快递超市、京东驿栈、速递易、递易、熊猫智能柜、日日顺乐家）；补别名（菜鸟裹裹→菜鸟、兔喜生活 / 兔喜快递柜→兔喜、喵柜→喵站）；新增 `stationMatch(in:)` 纯函数（仅 station/locker 类，最长关键词优先）。
  - **修复预存分类 bug**：`拼多多`/`多多` 作为平台词被放驿站类且 key 过短，导致 `【拼多多】` 被误识别为驿站。改拼多多 key→`拼多多驿站`（驿站类保留）、`多多`→`多多代收点`；并在电商类补 `拼多多` 平台条目（图标不变）。
  - `PickupModels.station`：废弃地址裁剪逻辑，改为 `CourierBrand.stationMatch(in:[rawMessage])?.name ?? ""`（纯品牌名，不匹配空）。`brandColor` 平台空时回落 courier。
  - `StationDirectory.matchedName`：复用 `stationMatch` + 自定义名叠加；3 处调用改为只传 `[record.rawMessage]`（地址不再参与驿站匹配）。
- 验证：独立 `swiftc` 编译 PickupParser/CourierBrand 跑 6 条字段 + 8 条驿站用例，全部符合新口径（含拼多多不再误报驿站）；全量 `xcodebuild` 编译验证进行中。
- 驿站统计来源：CNPP《2026 快递驿站十大品牌》+ 中国报告大厅《2025 快递代收十大》+ 智能柜榜单。
