## 真机测试时长问题：代码实测口径（主人 17:13 问）

主人问「装到真机测试，一轮测试时长多久」。这是**测试计划设计问题**，
答案取决于哪些功能有「时间门槛」。已grep 全工程核实如下。

### 有真实时间门槛的功能（决定了测试最短跨度的部分）

| 功能 | 参数 | 位置 |
|---|---|---|
| **「入库 N 小时未取」提醒** | 默认 **24 小时**（可UserDefaults `codeclip.reminderPendingHours` 改），用 `UNTimeIntervalNotificationTrigger(hours * 3600)` | `PickupNotifier.swift:204/267` |
| **每天固定时刻提醒** | 默认 **20:00**（key `codeclip.reminderDailyHour`），仅在有待取件时才排 | `PickupNotifier.swift:188/229` |

⚠️ **测试取巧法**：改 UserDefaults 把 pendingReminderHours 设为 1，1 小时即可验证提醒全链路，
不必真等 24 小时。`SIMCTL_CHILD_` 系列脚手架在真机上无效，但真机可用 Xcode
「Scheme → Run → Arguments」或直接 `defaults write`（真机需连 Xcode/证书）。

### 无时间门槛、即时可验的功能

- 待取/已取/统计/设置四标签 UI 与导航

- 驿站自定义增删改（`StationEditView`）+ 图标选择
- 快递管理页品牌画廊与分类网格

- 小组件各尺寸渲染
- 分享卡 / 末四位高亮 / 按驿站分组切换

### 🔴 灵动岛（Live Activity）无自动结束，时长是系统硬限制

`PickupActivityController.swift` 里**没有任何定时结束机制**——
全部是手动 `activity.end(nil, dismissalPolicy: .immediate)`（第93/123行），
且 `staleDate: nil`、`pushType: nil`（无远程推送更新）。

- App 侧不管它什么时候结束 → **由用户手动标记已取/删除时触发 end**；
- 系统侧上限：Live Activity 最长 **8 小时**（活跃）/ **18 小时**（后台累计），
  超过后系统自动丢弃。这是 ActivityKit 的硬限制，改代码绕不过。
- 因此测灵动岛时：若想验证「长时间挂起不崩」，最多跨 8 小时观察；
  若想验证内容刷新，**必须做多次标记/取消标记**来产生新事件。

### 结论：一轮完整测试的建议跨度

- **冒烟测试（UI + 编辑 + 地图 + 驿站管理）**：**30–60 分钟**，当天可完成。
- **功能全验（含提醒链路）**：改 pendingReminderHours=1 后 **约 2–3 小时**；
  不改则需**跨 24 小时**（等真实提醒触发）。
- **灵动岛专项**：单次事件 ≤8 小时，建议分两天各测一次早晚时段。
- **iCloud/多设备/后台唤醒**（若有）需单独留长，跨夜观察。

**建议排期**：Day1 冒烟 + 提醒链路（改 1 小时）→ Day2 灵动岛 8 小时观察 → Day3 补测。
