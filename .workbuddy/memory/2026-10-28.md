
## 09:32 左滑改「两段式」：先出圆钮，再滑才拉长
主人：「不管快慢向左滑，先出来圆形按钮，如果出来之后延时 0.几秒、还在一直向左滑才拉长按钮触发动作；
一般情况是轻轻左滑一下出来按钮，然后在这个状态再次向左滑，按钮才拉长」。

**旧实现的错**：`onChanged` 的 `maxTrailing` 直接给到 `trailingWidth + buttonWidth + 24`，
一次滑到底就能拉开 32pt 以上（`stretchCommitThreshold = 0.6 × 54 ≈ 32`），松手立即执行取件
—— 快速左滑等于"一划就取件"，误操作风险极高。

**现在（`SwipeActionRow`）**：
- `continuingFromOpen = dragStartOffset <= -(trailingWidth - 1)`：本次手势**起手位置**在展开位；
- 第一段（起手在关闭态）：`maxTrailing = trailingWidth + 8` —— 只能滑到按钮完全露出，
  8pt 是橡皮筋手感，远不到 32pt 阈值，**物理上不可能提交**；
- 第二段的两个入口：
  ① **抬手后重新左滑**（起手就在展开位）；
  ② **不抬手、在展开位停顿 ≥ 0.3s 再继续滑**（`openHoldStart` 计时；
     退回第一段范围会清零重新计时）。这就是主人说的"延时 0.几秒还在滑"。
- `onEnded` 提交条件收严为 `(continuingFromOpen || heldEnough) && trailingStretch > 阈值`；
- 右滑「直接复制」（`autoPerformSide == .leading`）保持不变。
⚠️ `stretchHoldDelay` 必须是**实例常量**：`SwipeActionRow<Content>` 是泛型类型，
`static let` 会报 `static stored properties not supported in generic types`。

## 11:01 真凶：Live Activity 不重新渲染（"改了没生效"）
主人连说两次「这不是还是没改吗，图标和待取数量被遮挡」——他不是在描述新布局坏了，
而是**压根没看到新布局**。

根因在 `PickupActivityController.apply`：
```swift
if list.contains(where: { $0.content.state == state }) {
    await enforceSingle(...); return      // 省 ActivityKit 更新预算
}
```
重装/升级 App 后 widget extension 换了新代码，但 `content.state` 一个字节没变
→ 命中这个分支 → **不 update → 系统不重新渲染** → 岛和锁屏卡一直停在旧样式。

修法：新增 `nonisolated(unsafe) private static var needsForcedRender = true`，
`apply` 里本进程首次收敛无条件 update 一次（`force` 为真就跳过那个 return）。
每进程一次，不浪费更新预算。

⚠️ `@MainActor` 修饰不了它 —— `apply` 是 nonisolated async；`sync` 的单飞
保证只有一条收敛链读写，所以 `nonisolated(unsafe)` 是安全的（注释已写理由）。

**教训：Live Activity / 小组件这类"由扩展渲染的 UI"，改完必须强制 update 一次，
否则用户看到的永远是旧画面，你怎么改他都说没变。**

## 13:46 小组件：数据少时行高/字号不再被拉伸
主人：「不管哪个尺寸的小组件，数据少的时候仍然不能改变字号、行间距」。

**根因**：`WidgetPagedContent` 的行是 `.frame(maxHeight: .infinity)` ——
行高按**剩余高度均分**。满页 8 条时每行 36pt，只有 2 条时每行被拉到 140pt，
视觉上就是"字变大了、行距变松了"，与满页完全是两种观感（字号其实没变，
是行框被撑高后内容居中、上下空白变多）。

**改法**：`GeometryReader` 量出列表区可用高度，行高 = `可用高 ÷ pageSize`（满页行高），

## 品牌取色统一到图标（2026-10-28 下午二）

### 根因
`CourierBrand.table` 的 `from` 是**手写常量**（82 条人工敲），而 `BrandPalette.swift`
是从官方 PNG 提取的（脚本生成）。图标画 asset、颜色取 `from`、详情玻璃卡取调色板
→ 三处两个源。丰巢手写青绿 `0x00C2A8`、图标黄蜂巢 `0xF3C50D`，于是黄底配青绿字。

### 主人的读色口径
「把图标模糊掉，那个颜色一般就是了」——模糊=按面积加权，但不能直接对整图求平均
（实测丰巢 `#D5C999`、顺丰 `#8D8989`，白底把它冲淡）。落地为：
**剔除近白 → 按面积取首色**（= 模糊掉白底之后剩下的那一块）。

### 脚本 `tools/extract_brand_palette.py` 改动
- 量化 8 → **24 档**，面积阈值 2% → **0.5%**（8 档会把顺丰红点、安能橙并进黑档）
- 排序：只保留「近白沉底，其余按面积」（试过「饱和度优先」，会把安能/抖音的黑底
  读成橙/粉红，与图标印象相反）
- 新增加宽降级：首色亮度 > 170 且饱和度 < 0.40（EMS 浅蓝、宅急送浅灰、多多代收灰白）
  → 换成后面第一个饱和度 ≥ 0.30 的候选
- 内部留 6 个候选供降级挑选，对外仍输出 3 个

重跑结果：51 个品牌**首色全部有辨识度**（0 条灰首色）。丰巢 = 黄 `0xF3C50D`。

### 代码改动（`CourierBrand.swift`）
```swift
Info.resolvedFrom   // ① manualColors 例外表 → ② 图标调色板首色 → ③ 手写 from
Info.ink            // 亮色品牌自动压暗（BT.601 亮度 > 0.66 → shade 0.62）
Info.color          // = ink（浅底 UI 一律用它）

```

### 🔴 锁屏卡玻璃第五版：自铺 .ultraThinMaterial（22:17）
**`whiten = 0` 是错的**：`activityBackgroundTint` 是「染色」不是「填充」，
锁屏是 dark 环境，ActivityKit 默认材质本身就是深色 —— 不染 = **纯黑块**，
深色文字全消失，只剩亮黄码浮在黑底（真机截图实证）。
白染 18%/34% 也只是把黑底调灰，永远得不到「亮且透」。

正解：
```swift
ActivityLockScreenCard(state:)
    .background { RoundedRectangle(cornerRadius: 24, style: .continuous).fill(.ultraThinMaterial) }
    .activityBackgroundTint(.clear)          // 清掉系统底本色，让我们的玻璃贴壁纸
```
`.ultraThinMaterial` 是**亮色**材质、会自适应壁纸明暗，所以文字必须一律深色
（码 islandInk、其余 black 0.85 / 0.62）。

⚠️ 教训：**不要在没验证的情况下把 tint 设为 0** —— 系统默认底不是透明的。
以后调锁屏卡底色，改的是「自铺材质 + 可选白染」，不要再碰 activityBackgroundTint 的透明度。

### 锁屏卡第六版：微信式液态玻璃配方（22:19）
参考主人给的微信通知卡：亮色磨砂 + 乳白 + 细高光边。实现：
```swift
.background {
    RoundedRectangle(cornerRadius: 24, style: .continuous)
        .fill(.ultraThinMaterial)                                   // ① 亮色磨砂
        .overlay { ...fill(Color.white.opacity(0.22)) }              // ② 乳白提亮
        .overlay { ...strokeBorder(Color.white.opacity(0.36), 0.8) } // ③ 高光边
}
.activityBackgroundTint(.clear)
```
⚠️ 待确认：上一版纯 ultraThinMaterial 在真机仍显示为黑块 —— 两种可能：
① 截图时活动还是旧渲染（Live Activity 视图要 update 才重绘）；已用
   `SCREEN=activityLive`（走 `PickupActivityController.sync`）强制推一次；
② ActivityKit 忽略内容层的 `.background`，则必须回到 `activityBackgroundTint(白色 0.55+)`。

### 🔴 锁屏卡「黑乎乎」的真正根因（22:22 定论）
**`.ultraThinMaterial` 会跟随环境外观渲染**。锁屏是 dark 环境，所以直接铺 material
得到的是**深灰磨砂** —— 无论怎么调白染都是"黑乎乎"，因为材质本身就是深色底。

正解：给背景层**强制 light 环境**
```swift
.background {
    ZStack {
        Rectangle().fill(.ultraThinMaterial)
        Color.white.opacity(0.18)
    }
    .environment(\.colorScheme, .light)     // ← 关键
    .clipShape(RoundedRectangle(cornerRadius: 24, style: .continuous))
    .overlay { RoundedRectangle(...).strokeBorder(.white.opacity(0.40), lineWidth: 0.8) }  // 微信那圈高光边
}
.activityBackgroundTint(.clear)
```
预览三档验证：浅色壁纸→乳白雾面；深色壁纸→灰白（材质仍透底，正常）；码金黄清楚。

⚠️ 以后凡是「在锁屏/深色容器里要亮色材质」，都得 `.environment(\.colorScheme, .light)` 包一层，
不能指望 material 自适应成亮的。

## 🔴 锁屏卡最终方案（2026-10-28 22:25）· 停止在 Material 上试错

### 教训（重要，别再犯）
1. **ActivityKit 锁屏上下文里，`.ultraThinMaterial` 被系统按 dark 强制渲染**，
   `.environment(\.colorScheme, .light)` 也压不住（真机连试两次都是深灰）。
   材质这条路在锁屏卡上不通 —— 不要再改 material 档位/白染值。
2. **`activityBackgroundTint` 是染色不是填充**，设 0 = 系统深底原样露出 = 黑块。
3. **Live Activity 视图有系统缓存**：改代码不换活动实例，锁屏可能一直显示旧渲染。
   验证前必须 `end()` 全部在册活动再 `sync()` —— 已写进 `SCREEN=activityLive` 脚手架。

### 定案
```swift
.background {
    RoundedRectangle(cornerRadius: 24, style: .continuous)
        .fill(Color.white.opacity(0.78))                 // 半透明白，任何壁纸都呈浅乳白
        .overlay {
            RoundedRectangle(cornerRadius: 24, style: .continuous)
                .strokeBorder(Color.white.opacity(0.55), lineWidth: 0.8)  // 高光边
        }
}
.activityBackgroundTint(.clear)
```
纯色，不依赖环境；深色文字对比天然成立（码 islandInk / 平台名 black 0.85 / 地址 black 0.62）。
预览三档已确认：浅、深、中三种壁纸下都是浅乳白卡 + 金黄码。

### 可调项
`white.opacity(0.78)` —— 降 = 更透、升 = 更白。这是唯一需要调的数值。

## ✅ 锁屏卡液态玻璃：UIKit 亮色模糊（2026-10-28 22:29 收工）

### 唯一可行的实现
```swift
// 定义在 CodeClipShared/PickupActivityAttributes.swift（两个 target 都编译）
struct LightGlassBackground: UIViewRepresentable {
    var style: UIBlurEffect.Style = .systemThinMaterialLight

```

### 为什么只有它能成
- SwiftUI `.ultraThinMaterial` 在锁屏被系统强制 dark 渲染，`.environment(\.colorScheme, .light)` 无效；
- `UIBlurEffect.Style` 有**显式亮色变体**（`system*MaterialLight`），与外观无关 —— 这是关键差异；
- `activityBackgroundTint` 是染色，不是填充。

### 🔴 工程坑
`CodeClipShared/` **不是** PBXFileSystemSynchronizedRootGroup（同步组只有 `CodeClip/`），
新建共享文件不会自动进 target。新增共享代码要么手动登记 pbxproj，**要么直接并进已有共享文件** ——
这次是并进 `PickupActivityAttributes.swift`，零工程改动。

### 可调项
`whiten` 0.20（白度）、`style` `.ultraThinMaterialLight`(更透) / `.thinMaterialLight`(当前) / `.materialLight`(更实)。
预览脚手架 `SCREEN=lockPreview` 与真实活动用同一个组件，所见即真机。

### ❌ UIVisualEffectView 方案也失败：材质被活动 tint 染成品牌色（22:30）

但**模拟器预览复现不了**这个现象（预览一直是乳白），无法本地验证 → 不再赌。

## ✅✅ 锁屏卡液态玻璃：用 Apple 原生 `glassEffect`（2026-10-28 22:33）

主人指名「iOS 27 的液态玻璃材质，Apple 的原生组件」—— 之前全在白忙活，

### 正确 API（SwiftUICore，iOS 26+，工程 target 27 直接用）
```swift
.glassEffect(.regular, in: .rect(cornerRadius: 26))
```
- `Glass.regular` / `.clear` / `.identity`，可 `.tint(Color?)`、`.interactive()`
- 声明位置：`SwiftUICore.swiftinterface:3085`

## 锁屏卡文字自适应（2026-10-28 22:38）
主人问「怎么根据壁纸颜色自动切换文字深浅」→ 答案：**用语义色**。
Liquid Glass 上的 `.primary` / `.secondary` 带 vibrancy，系统按玻璃下实际明暗自动翻转黑白。
之前手写 `Color.black.opacity(0.85/0.62)` 等于把这套自适应关掉。

改动：平台名 `.primary`；地址/柜位/「还有 N 条」→ `secondaryInk = .secondary`。
码保留品牌色（`islandInk` 轻压），它是唯一需要"品牌识别"的元素。

## 锁屏卡文字：白字 + 深色描影（2026-10-28 22:41 定稿）

`.primary` 在 Live Activity 里固定给白色、不会按玻璃明暗翻转（实测），
白字 + 浅玻璃 = 糊。改用壁纸类场景的通用解法：**白字 + 深色描影**，两头通吃。

| 元素 | 颜色 | 描影 |
|---|---|---|
| 快递公司/驿站 | `.white` | black 0.40 / r2 |
| 地址、柜位、「还有 N 条」 | `.white 0.80` | black 0.40 / r1.5 |
| 取件码 | 品牌色（`islandInk` lum≤0.62） | black 0.40 / r2.5 |

统一常量 `inkShadow`，改一处全卡生效。
