### Mac 端发码工具：双击打不开窗口的根因与修复（2026-09-24 22:40）
- **现象**：`tools/license-gen/macapp/build/发码.app` 用 `open`（= Finder 双击路径）启动后窗口不上屏 / 0×0；终端里直接执行同一个二进制却正常（窗口 1000×752）。
- **根因（已取证定案）**：仓库在 `/Volumes/ZWN`（**外挂 APFS 卷**，`noowners` 挂载）。`open` 启动的 App 读该卷文件时，`stat()` 0ms 返回 true，但 `open()` 在**内核里永久挂起** —— 系统要弹「可移除宗卷」授权框，而那个框弹到了**副屏**（副屏在主屏左侧、坐标为负，实测 `410×342 @ -1165,136`；屏幕布局 `(0,0,1920,1080)` + `(-1920,0,1920,1080)`）。副屏没接/没开时框看不见，`open()` 永远等不到响应。终端执行时进程继承终端磁盘权限，所以正常。
- **取证链**：`sample <pid>` 主线程栈精确停在 `libsystem_kernel: open`；同进程 A/B（读 `/tmp` 1ms 成功 → 读外挂卷挂死）排除「盘慢 / 文件不存在」；延迟 10s 再读仍挂 → 排除「启动期竞态」；最小 App bundle 独立复现。
- **架构修复**：`LicenseCore` 引入**本机工作目录** `~/Library/Application Support/CodeClipIssuer/`（`keyURL`/`ledgerURL` 全指向此处）；仓库目录降级为「导入来源」`sourceDir`；`importFromSource` 走后台线程 + **3 秒看门狗**（`asyncAfter`）兜底；`importKey(from:)` 走 `NSOpenPanel` 手动导入。`MainViewController.loadView()` 内**不再有任何跨卷 IO**，改到 `viewDidAppear` 才发起导入。窗口尺寸 780×580 → **1000×720**（minSize 860×620）。
- **配套**：新增 `tools/license-gen/同步发码数据.command`（双击运行：容器缺私钥则导入 + 台账按已签发条数双向同步，多者为准）；`README.md` 增「Mac 端图形工具」章节记录此坑。
- **验证**：`open` 路径窗口 `onscreen=true | 1000×752`、生命周期日志完整；端到端签发 `#0003`（归一化 `AABBCCDDEEFF00112233445566778899`、回验 valid=true、篡改尾字符 valid=false）；同步脚本把容器 3 条写回仓库成功。验收数据已清理，两边台账恢复 2 条且逐字节一致。

### 发码.app 图标：程序化绘制 + macOS 规范适配（2026-09-24 22:55）
- **产物**：`macapp/icon/make_icon.swift` —— 不依赖设计稿，纯 CoreGraphics 程序化绘制图标，改顶部常量重跑即可出 `.icns`。跑法 `xcrun swift icon/make_icon.swift`。
- **设计口径**：延续码夹品牌基因 —— 亮蓝渐变底（`#4E9EFF`→`#1361CB`）+ 三层卡片叠放（白 / 青绿 `#40E2D0` / 橙黄 `#FFC040`）+ 蓝色四角扫描框（`#1B6FE0`）。按 macOS 规范重绘：1024 画布 + **824 内容体居中** + **自绘超椭圆 squircle**（n=5，macOS 不会替 App 加圆角）。
- **小尺寸变体**：≤32px 改用「单卡 + 加粗扫描框」（线宽 50 vs 完整版 32），因为三层叠片在 16px 下必糊成一团；iconset 里 16/32 走简化版、64 以上走完整版。
- **接入构建**：`build.sh` 自动拷 `AppIcon.icns` 进 bundle + `Info.plist` 声明 `CFBundleIconFile`，构建末尾跑 `lsregister -f`。`.gitignore` 补 iconset / compact / build 中间产物。
- **踩坑四条（已写入 `macos-app-dev-pitfalls`，并修正了该技能里一条错误旧记录）**：
  1. 声明 `CFBundleIconName` 但工程里没有 `Assets.car` → 系统回退到**通用底板**（浅灰圆角方 + 缩小的图标内容）。纯 icns 场景只写 `CFBundleIconFile`。
  2. `lsregister -f` 之后图标缓存要**数十秒**才生效，期间 `NSWorkspace` 读到的可能仍是通用底板 —— 是过渡态，不是图标有问题。
  3. 判断「有没有套通用底板」**不能采四角像素**（底板自身也有圆角、四角同样透明），要采**边缘中点**（底边中央 `(w/2, 8)`，`(0,0,0,0)` 才算无底板）。
  4. `iconutil` 把 16/32px 存成**老式 RAW 槽位**（`ic04`/`ic05`），PNG 槽位是 `ic11`/`ic12`/`ic07`…`ic10`；用 `CGImageSource` 按 `img.width` 分组去重会**取错槽位**。
- **验收**：`NSWorkspace.icon(forFile:)` 返回 32 个表示层（16→2048 完整链）；三路对照（系统 API / 直接读 icns / 设计原图）渲染完全一致，边缘中点全透明 → 确认无底板；`open` 双击启动窗口仍 `1000×752 | onscreen=true`。验收图 `macapp/icon/图标验收.png`。

### 发码.app UI 重构：液态玻璃 + 深浅双外观（2026-09-24 23:35）
- **触发**：主人反馈「明亮模式太难看」，要求上 **macOS 27 液态玻璃**、遵循 Apple 设计规范、借鉴优秀按钮。附了浅色下的截图。
- **根因（颜色）**：`layer.backgroundColor = 动态色.cgColor` 把**当时外观**的颜色固化进 layer，外观切换不跟随 —— 于是「浅色窗口 + 深灰卡片 + 近黑输入框」。`NSTextField.textColor` 不受影响（每次绘制重解析），所以只有 layer 部分是坏的。
- **修法**：抽出 `ThemedView` 基类，override `viewDidChangeEffectiveAppearance()` → `applyTheme()`，全部用 `effectiveAppearance.performAsCurrentDrawingAppearance { }` 包住解析。覆盖 6 处（`PillButton`/`FieldBox`/`CardView`/`HairlineView`/`ChipView`/`MultilineField`/`ResultRowView`）。
- **根因（布局，两坑叠加）**：
  1. `makeSpacer()` 只压了水平方向 —— 空 `NSView` 无 `intrinsicContentSize`，**hugging 完全不生成约束**，在水平栈里被拉伸到填满可用高度，**把顶栏撑到 328pt**。
  2. 同一机制下 `NSStackView` 自身 `intrinsicContentSize` 也是 `-1×-1`，链式约束高度解不唯一 → 内容区只剩 350pt、结果区被压成 **10px**。
  - 合起来的表现就是「窗口下方一大片空白」。修法：顶栏/底栏/页头**钉死高度**（`T.headerHeight=64` / `T.footerHeight=42`）；`makeSpacer()` 加显式 `height == 0`；列容器改 `NSStackView(distribution: .fill)`（注意 `.fill` rawValue 是 **0**、`.gravityAreas` 是 **-1**）。
- **液态玻璃落地**：`CardView` 用 `NSGlassEffectView`（macOS 26+）；玻璃作**同级背景层**（不用 `glass.contentView` —— 那条路会让卡片在垂直栈里彻底失去伸展能力），content 后添加盖在其上。按钮不走玻璃：`PillButton` 改自绘胶囊（`draw(_:)` 画在标题**之下**，sublayer 会盖住系统绘制的标题），主按钮 = accent 渐变 + 顶部掠射高光 + 轻投影 + 阴影路径，次按钮 = 半透明白玻璃底 + 细描边。`Info.plist` 最低系统版本提到 **26.0**。

## 发码.app 打包安装到「应用程序」（23:52）

## 台账/签证结果行改「单行显示」

- 主人反馈：「窗口这么大，为啥为上下挤在一起，一条数据你就一行显示不就行了」。
